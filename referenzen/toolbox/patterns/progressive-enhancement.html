Progressive Enhancement

Die Seite ist in jedem Browser lesbar. Ein neueres Feature verbessert sie in den Browsern, die es unterstützen. Ein Ersatz mit @supports gilt in den übrigen Browsern.

CSS-Architektur

Nicht jeder Browser kann alles

Demo

Code

Warum

Ein Browser verwirft CSS, das er nicht kennt. Eine unbekannte Eigenschaft oder ein unbekannter Wert verwirft die Deklaration. Ein unbekannter Selektor in einer Selektorliste verwirft die ganze Regel. Der Browser meldet das nicht in der Console.

Viele Features fallen ohne Schaden weg. Ohne text-wrap: balance brechen Überschriften wie gewohnt um. Für einen festen Wert genügt ein Ersatzwert in einer Deklaration davor.

Bei einer Custom Property genügt das nicht. Der Browser prüft ihren Wert erst beim Einsetzen. Ohne light-dark() ist jede Deklaration mit einem Farb-Token ungültig: Der Hintergrund ist transparent, der Text erhält seinen Anfangswert. Im Dark Mode steht dann schwarzer Text auf dunklem Hintergrund.

Die Bedingung @supports not (color: light-dark(white, black)) trifft nur in Browsern ohne light-dark() zu. Der Block legt dort die Farben des Light Mode fest. Die Bedingung nennt eine Eigenschaft mit festem Wertebereich: Mit einer Custom Property trifft sie immer zu.

Barrierefreiheit

  • Ohne Ersatz ist der Text in einem Browser ohne light-dark() im Dark Mode nicht lesbar. Der Browser meldet keinen Fehler.
  • Der Ersatz legt nur den Light Mode fest. Die Seite ist lesbar, folgt aber nicht der Einstellung der Person.
