Label und Fehlermeldung

Ein Label gibt einem Feld seinen Namen. Ein Pflichtfeld prüft der Browser: Er zeigt beim Absenden eine Fehlermeldung, und das Style­sheet markiert das Feld erst nach einer Eingabe.

Code

Warum

<label> verbindet einen Text mit dem Feld, dessen id das Attribut for nennt. Der Text ist der Name des Felds im Accessibility Tree, und ein Klick auf das Label setzt den Fokus in das Feld. Ein Placeholder erfüllt diese Aufgaben nicht: Er verschwindet bei der Eingabe und ist keine Klickfläche.

<fieldset> fasst Felder zu einer Gruppe zusammen, <legend> benennt die Gruppe. Radio Buttons mit demselben Wert in name bilden eine Auswahl, in der höchstens einer gewählt ist.

Das Attribut required kennzeichnet ein Pflichtfeld. Der Browser sendet das Formular nur mit einem Wert in diesem Feld ab und zeigt sonst eine Fehlermeldung am Feld. Das Style­sheet markiert das Feld mit dem Selektor :user-invalid. Er trifft erst zu, nachdem die Person das Feld bearbeitet oder das Formular abgesendet hat. :invalid trifft dagegen schon beim Laden der Seite zu.

Das Formular der Demo sendet seine Daten mit method="get" als Teil der URL an DuckDuckGo: je Feld ein Paar aus name und Wert.

Barrierefreiheit

  • Jedes Feld hat ein Label. Screenreader sagen den Namen an, wenn das Feld den Fokus erhält.
  • Das <fieldset> hat die Rolle group und den Namen aus <legend>. Ohne Gruppe fehlt zu „MDN“ die Angabe, worauf sich die Auswahl bezieht.
  • Tastatur: Tab erreicht das Feld, den gewählten Radio Button und den Button. Die Pfeiltasten wechseln zwischen den Radio Buttons, Enter sendet das Formular ab.
  • Die Markierung eines ungültigen Felds besteht aus einem Balken und einer Farbe, nicht aus der Farbe allein.
