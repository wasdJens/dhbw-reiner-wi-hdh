Cascade Layers

Eine Ebene fasst Regeln eines Style­sheets zusammen. Die Reihenfolge der Ebenen entscheidet vor der Spezifität der Selektoren, welche Deklaration gilt.

Warum

Treffen zwei Regeln mit derselben Eigenschaft auf ein Element zu, entscheidet die Kaskade in drei Schritten: Ebene, Spezifität, Reihenfolge im Quelltext. Eine Regel in einer späteren Ebene gewinnt gegen eine Regel in einer früheren Ebene, unabhängig von der Spezifität der Selektoren.

Ohne Ebenen entscheidet die Spezifität zuerst. Eine Komponente überschreibt die Regel für ein Element dann nur mit einem spezifischeren Selektor oder mit !important. Mit Ebenen genügt ein Selektor mit einer Klasse, weil die Ebene components nach der Ebene base steht.

Die Ebene overrides steht zuletzt. Eine eigene Gestaltung in overrides.css gewinnt deshalb gegen jede Regel der anderen Dateien, ohne dass diese Dateien sich ändern.

Eine Regel außerhalb jeder Ebene gewinnt gegen alle Ebenen. In der Toolbox steht deshalb jede Regel in einer Ebene.

Die Anweisung @import steht vor allen Regeln einer Datei. Steht sie nach einer Regel, lädt der Browser die Datei nicht und meldet keinen Fehler.

Barrierefreiheit

  • Die Regel für den sichtbaren Fokus (:focus-visible) steht in der Ebene base. Eine Regel außerhalb der Ebenen mit outline: none entfernt den Fokusrahmen auf jeder Seite, auch mit einem Selektor geringerer Spezifität.
  • Ebenen ändern weder die Reihenfolge der Elemente noch den Accessibility Tree.
